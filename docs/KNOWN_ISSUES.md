# Known issues and limitations

Honest list of what does not work, works only partly, or has not been verified. Items are ordered by how
much they matter to a deployment. "Verified" always means "run in this repository's test setup"; where something
was only compiled or reasoned about, it says so.

## Detection quality

| # | Issue | Impact | Mitigation / status |
|---|-------|--------|---------------------|
| 1 | **Person / organization / free-form address detection (Chinese and English) is rule-based only.** By product decision no statistical or ML model is used (GLiNER and spaCy NER were removed). Names are found only by labelled patterns (`cn-name-labeled`, e.g. "姓名：…"), possessive patterns (`cn-name-possessive`) and dictionaries; addresses only by the province-anchored rule `cn-address`; organizations only by dictionaries/patterns. **Unlabelled names and free-form company names WILL be missed**, as will addresses that do not start with a province/city anchor. | Names, company names and free-form addresses can slip through when no rule or dictionary entry matches. | Extend the dictionaries and rules for your domain; Presidio contributes only deterministic recognizers (phone, email, credit card, IBAN, crypto, US ids). |
| 2 | **Dictionary / pattern hits on public-figure or common words are reported as PERSON.** Whether a matched name is sensitive depends on policy. | Over-masking in general-knowledge text. | Policies can lower the PERSON action to `audit`. |
| 3 | **The accuracy dataset is synthetic and generated by the same authors as the rules.** Numbers are in-distribution and optimistic for rule-detected types (see ACCURACY_REPORT "Threats to validity"). | Real-world precision/recall will be lower, in particular for names and organizations. | Bring your own labelled corpus: `benchmarks/accuracy/eval.py` takes any JSONL in the same schema. |
| 4 | **Digit-boundary semantics.** CN phone / ID / bank-card rules do not match inside a longer ASCII-digit run (`913800138000` is not a phone). Numbers separated from letters (`tel13800138000x`) *are* masked. | A phone number embedded in a longer numeric id is deliberately not reported. | By design (avoids false positives on order/serial numbers). |
| 5 | **Gitleaks "decoding passes" (base64/hex/percent/unicode-escape layers) are not implemented.** The 223 upstream rules and the keyword/entropy/allowlist/required-rule semantics are ported and checked for parity on plain text; secrets that are only visible after decoding a base64 blob are not found. | Encoded secrets. | Not planned for this version. |
| 6 | **Inline `gitleaks:allow` comments are deliberately ignored.** A user-controlled comment must not be able to disable DLP. | Differs from the upstream CLI on purpose. | Documented in GITLEAKS_PARITY.md. |

## Throughput

| # | Issue | Impact |
|---|-------|--------|
| 18 | **The Presidio NLP path is ~50–100× slower than the Rust rules** (≈12 ms per 1 KB vs. 0.2 ms; ≈14 s per 1 MB; PERFORMANCE_REPORT.md). Under heavy concurrency the engine sheds NLP work and answers from rules alone with `degraded:true` (or blocks when the policy makes `presidio` mandatory, e.g. `strict`). | Use `strict` only with enough NLP workers (`DLP_NLP_WORKERS`) or accept blocking under load; the rules path has no such limit. |
| 19 | Texts above ~1 MB are rejected by the NLP service (413) and inputs that exceed its 25 s budget are reported as a detector error. | Degraded or blocked per policy, never reported clean. |

## Streaming

| # | Issue | Impact |
|---|-------|--------|
| 7 | **`window` stream mode is unavailable with the default rule set.** Window mode needs a provable maximum entity length; the Gitleaks private-key rule and a few others are unbounded, and the NLP service's recognizers are not bounded. The engine therefore falls back to `strict` (buffer until the terminal event) and says so in the stream stats (`fallback_reason`). | Strict mode adds the full generation time as latency for the first visible byte. Window mode is only effective with a restricted rule set. |
| 8 | Delta text is treated as one concatenated channel per content block, as clients render it. Two separate events that each contain a complete number therefore form one longer digit run for the digit-boundary rules. | Cosmetic; matches what the end user sees. |
| 9 | OpenAI *Responses* API `annotations` indices (`start_index`/`end_index`) are not re-mapped after masking changes the text length. | Citation highlights can be off after masking. |
| 10 | SSE only. WebSocket and gRPC streaming are not implemented. | |

## Platform / build

| # | Issue | Impact |
|---|-------|--------|
| 11 | **Windows**: the x86_64-pc-windows-gnu cross-build was produced and the CLI/FFI smoke test ran under **wine**, not on a Windows host. The MSVC toolchain build and the PowerShell scripts in `scripts/windows/` were **not executed**. | Treat Windows support as "builds, passes smoke tests under wine"; run `scripts/windows/test.ps1` on a real host before relying on it. |
| 12 | Hyperscan is loaded at runtime via `dlopen`/`LoadLibrary` and used only as a prefilter for keyword-less rules; if the library is absent the portable regex path is used (results identical, verified). On Windows no Hyperscan binary is shipped. | Slower on very large inputs without Hyperscan. |
| 13 | Removed: GLiNER, ONNX, torch/transformers and all trained spaCy models were dropped from the product by decision. The NLP service runs only Presidio's deterministic recognizers; there are no model weights to fetch, evaluate or secure. | |

## Security / operations

| # | Issue | Impact |
|---|-------|--------|
| 14 | **The Token Vault is in memory only.** Restarting the server loses all placeholders; reversible anonymization cannot be restored after a restart. | By design (no plaintext secrets on disk). A persistent encrypted vault is future work. |
| 15 | The NLP service listens on loopback and uses an optional shared token; it has no TLS. It must not be exposed beyond the host. | |
| 16 | No rate limiting per tenant beyond the global `--max-inflight` and per-request size limits. | |
| 17 | `cargo audit` / `pip-audit` results are a snapshot (THIRD_PARTY.md, 2026-10-22); the vulnerability databases are not refreshed automatically. | |

## Fixed during development (kept for traceability)

* SSE `event:`/`id:`/comment fields and non-JSON data events were forwarded unscanned. Found by the random-input
  robustness test (`crates/dlp-engine/tests/robustness.rs`), fixed in commit `0a489ae`; regression test
  `sse_metadata_fields_and_non_json_events_are_scanned_too`.
* Presidio analysis was superlinear (100 KB 7.5 s, 1 MB > 120 s) and kept running after the caller gave up; fixed with chunking + time budget. uvicorn multi-process mode added a 40 ms Nagle stall; fixed with an own TCP_NODELAY listener (PERFORMANCE_REPORT.md).
* ASCII `\b` made CN phone/ID/card rules miss numbers glued to letters; replaced by the `digit_boundary` validator.
