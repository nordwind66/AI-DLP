# Accuracy report

Generated by `benchmarks/accuracy/eval.py` (+ `report.py` for these tables), commit-time numbers, **no model in the
pipeline**: detection is regex + checksum validators + Gitleaks rules + dictionaries + Presidio's deterministic
recognizers. Re-run: `python benchmarks/accuracy/eval.py && python benchmarks/accuracy/report.py`
(needs dlp-server and the NLP service running; see docs/BUILD_LINUX.md).

## Dataset and method

* `tests/data/accuracy/dataset.jsonl`, built by `tests/data/accuracy/build_dataset.py`: **677 texts, 790 gold entities,
  179 negative texts** (no entity expected). Chinese, English and mixed; categories: chat, code, JSON, markdown, long
  documents, PII sentences, credentials, confusables (order/serial numbers shaped like phones), 3-Han-character
  non-names, wrong-checksum IDs, pseudo keys.
* Matching is one-to-one greedy per (text, entity group). **lenient** = IoU ≥ 0.5, **strict** = identical span.
  Predictions of groups that are not in the gold label set are ignored, not counted as false positives.
* Systems: *unified* (all detectors, merged and resolved by the engine), *unified rules-only* (regex+secret+dictionary,
  no NLP service), *presidio alone* (the NLP service endpoint directly), *gitleaks upstream* (the real Go library run
  by `gl_difftool`, default config, decoding off), *secret detector alone* (this engine's `secret` detector =
  the 223 imported Gitleaks rules **plus** the built-in credential rules, which is why it can differ from upstream).
* FNR = 1 − recall. Text-level FPR = share of negative texts with at least one false alarm.

## Reading the numbers

* **Structured identifiers are solved at the level this dataset can measure**: phone, CN ID card, bank card, e-mail,
  passport, internal IP/domain, DB connection strings, credentials and province-anchored addresses all reach P = R = 1.0
  with zero false alarms on the 179 negatives, including the confusable categories (order numbers shaped like phones,
  wrong-checksum IDs, three-character non-names, pseudo keys).
* **Names and organizations are the weak spot, by construction.** Without a model, a person is recognised only when a
  rule sees a signal: a label (`联系人：`, `姓名:`), a possessive/role pattern (`张三的手机号`) or a dictionary entry,
  plus the surname/shape validator for Chinese names. Result: Chinese PERSON recall 0.57; **English and mixed-language
  PERSON recall 0.00** (the dataset's English names appear in free prose such as "Please contact Alice"); ORGANIZATION
  0.00. Precision stays 1.0 because nothing without a signal is reported. For a desensitisation product this means
  *free-text names and company names will pass through unmasked* unless they are in a dictionary or labelled.
  Levers that need no model: customer/employee dictionaries (`dictionaries` table, hot-reloadable), more
  context-pattern rules, and policies that mask whole labelled fields. See KNOWN_ISSUES.md #1.
* The previous revision of this project had GLiNER in the pipeline; a probe on the same Chinese PERSON cases measured
  F1 0.99 with a CJK-aware splitter (git history, commit `9a59a7a`). That component was **removed by decision** (no
  model-based detection) and its numbers are not part of this report.
* **Presidio alone** reaches only 0.22 recall because it covers phone/e-mail/card/IBAN and nothing China-specific
  (ID card, address, secrets).
* **Gitleaks upstream** misses 12/132 credentials and raises 8 false alarms on this dataset; the engine's `secret`
  detector gets 132/132 with 0 false alarms because it also carries the built-in key=value / DB-URL / private-key
  rules and the placeholder allowlist. This is a different rule set, not a faster Gitleaks: byte-for-byte parity of the
  imported Gitleaks rules themselves is checked separately (GITLEAKS_PARITY.md, 0 diffs on the parity corpus).

## Threats to validity (read before quoting any number)

1. **The dataset is synthetic and written by the same people who wrote the rules.** Perfect scores on rule-detected
   types mean "the rules do what their authors intended on these templates", not "99.9 % in production".
   Real traffic has more formatting noise (spaces inside numbers, full-width digits, line breaks, OCR errors).
2. Addresses score 1.0 because the generated addresses all start with a province/city/district the rule anchors on;
   free-form addresses ("学院路旁边那个小区3栋") are not covered and not in the data.
3. English PERSON/ORG recall of 0 is an honest lower bound for the rules-only design on prose; labelled English
   forms ("Name: John Smith", "Dear Mr. Lee") are only partly covered.
4. 677 texts is small: one error moves a per-type recall by 1–4 points for types with 25–50 entities.
5. No cross-validation against a third-party labelled corpus was run (none is available offline in this environment).
